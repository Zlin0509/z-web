# Zlin Trading Service

独立部署的私人交易研究服务，美股与虚拟币共用日线 / 15分钟研究引擎，拥有独立的 D1 数据库和 Sites 身份边界。博客只链接到本服务，不代理账户或策略数据。

## 已实现

- OKX USDT 现货公开日线（仅确认完成的 UTC K 线）、Alpaca IEX / Alpha Vantage 美股日线适配器、CSV 导入。
- SMA20、EMA20、Wilder RSI14、MACD12/26/9、布林带20、Wilder ATR14、20 日年化历史波动率。
- 双均线、RSI 回归、通道突破三种参数化策略；可保存回测结果、交易流水和权益曲线，导出 JSON。
- 持续模拟策略：新完成的对应周期K线触发推进；仓位上限、手续费、滑点、回撤停机、版本 CAS 和时间水位防重复；一键停止。
- DeepSeek JSON 分析适配器，服务端密钥，响应验证、调用间隔、分析留档；只产生研究建议。
- OKX 模拟/实盘密钥隔离，账户余额、现金现货限价单、撤单及成交查询；模拟盘支持策略自动执行，实盘逐笔确认并受服务器开关控制。

## 运行与部署

Node >=22.13。在本目录执行 `npm ci`、`npm run dev -- --port 4322`。本服务有独立 package.json、Worker、数据库迁移和 `.openai/hosting.json`，可脱离博客目录部署。代码同时保存在主 GitHub 仓库的 services/trading。

本地模拟登录由官方 Sites 插件提供，`.dev.vars` 使用 `TRADING_OWNER_EMAIL="seedy@sites.test"`。生产保留 Sites 当前访问范围；应用内交易数据和操作始终要求所有者通过 ChatGPT 登录；首次以已验证的 owner email 绑定 Site-scoped user ID。配置项见 `.env.example`，不得把密钥写入 Git、浏览器或日志。

构建：`npm run build`。本地 D1 初始化：构建后执行 `node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_*.sql`，替换通配符为实际迁移名，且仅执行未应用迁移。生产由 Sites 在部署时应用迁移。

## 数据库展示与定时同步

页面行情读取只访问服务端 D1 数据库，不调用行情供应商，不开启 WebSocket、不进行15秒报价轮询或60秒页面重载。`/api/state?asset=...` 一次返回列表与选中标的日线；同一页面按 revision 复用标的日线。回测列表只返回摘要，完整曲线和交易通过 `/api/runs/:id` 按需加载。「读取数据库」仅重新读取持久数据，「更新行情入库」才触发写入同步。

报价每5分钟在后台采集一次：所有美股合并为一次 Alpaca IEX 请求，虚拟币合并为一次 OKX SPOT tickers 请求。接口故障保留上次成功值和原始行情时间，显示错误；重复任务用租约和290秒缓存阻止重复采集。报价是定时快照，并非逐笔实时数据。

完整日线单独更新：虚拟币已有昨天的完整 UTC 日线时不请求；美股成功检查后6小时内复用数据库，休市也避免每5分钟重复拉取。Alpaca 首次取550天，后续从最新日线向前重叠3天；OKX 根据缺口缩小请求条数。历史以标的、来源、年份归档到 service_state 的 `history:*` 记录，按时间去重和修订；图表/回测活跃窗口保留最近2000根，旧数据继续留在年度归档。来源切换保留原来源归档，避免混合复权口径。

站点保留公开入口，业务 API 仍要求所有者登录。后台 `/internal/refresh` 和 `/internal/status` 使用独立 HMAC-SHA256 同步凭证，签名绑定时间、方法与路径，5分钟过期；拒绝浏览器 Origin。平台 bypass token 本身无写入权限。同步凭证不能访问账户、策略编辑或订单 API。

运行器：`scripts/sync-market.py --config /home/zlin/.config/zlin-trading/sync.json`。配置文件0600，凭证通过 curl 标准输入传递，不进入 Git、命令行或日志；服务端秘密名 TRADING_SYNC_SECRET。部署后使用当前服务器的用户 crontab 每5分钟执行一次，flock 防止重叠。最近结果保存在同目录 last-status.json。此计划依赖服务器和 cron 在线，重启后继续；原 Sites 每日任务缺少新签名凭证，不作为同步路径，当前工具无法修改它。

## 回测口径

可选日线或15分钟，多头、无杠杆，可模拟碎股。完成预热后，t-1 收盘信号在 t 开盘按滑点和单边手续费成交；买入持有基准使用同一起点和买入成本。期末持仓按市价估值，胜率仅包含已平仓交易，0笔成交时胜率为空。日线波动率/夏普用365（虚拟币）或252（美股）年化；15分钟分别用365×96和252×26。回撤触线后在下一可用K线开盘模拟退出，跳空可能超过阈值。

模拟启动时记录最新对应周期K线时间，不追溯生成历史订单。数据缺口导致时间水位不在已保留窗口时暂停。模拟只用于研究：它根据已完成K线重建假想开盘成交，不能验证真实流动性、滑点或订单延迟。

普通行情与模拟执行使用未复权 OHLCV；AI研究另有拆股复权缓存。普通行情回测，不计股息、拆股、税费或停牌流动性。跨公司行动比较请导入一致复权的 OHLC。导入会替换该标的样本并切换为 CSV 离线模式。勿将短样本回测理解为实盘表现。

## 网页连接配置与最新报价

登录后进入「服务接入」，下方「密钥配置与 Schwab 账户」可填写 DeepSeek API Key、Alpaca Key ID/Secret、Schwab App Key/Secret。密钥在服务端用 AES-256-GCM 加密存入 D1，主密钥 CONFIG_ENCRYPTION_KEY 保存在 Sites secrets；配置接口只返回已配置状态，输入空白保留旧值。切勿直接轮换主密钥，否则旧配置无法解密。

最新报价和回测日线分别保存于数据库；页面只读取快照，后台批量刷新，明确标注来源与行情时间。概览指标使用完整日线，策略使用所选周期的完整K线。

Schwab 回调地址为 `https://zlin-trading-lab.zlin20050509.chatgpt.site/schwab/callback`。注册应用需要 Accounts and Trading Production；Market Data Production 可按需申请，本版美股报价使用 Alpaca。网页通过顶层 OAuth 授权，服务端加密保存和刷新令牌；失效后需重新授权。支持账户/持仓/近7日订单读取、普通时段DAY股票整股限价单预览与提交、撤单。单笔最多1000 USD；预览60秒过期，提交一次性领取，超时结果未知时不自动重发。

本地预览不是 Schwab 券商预检。真实提交和撤单受服务端 SCHWAB_LIVE_TRADING_ENABLED=true 开关保护，网页无法启用该开关。当前无真实凭证，尚未完成券商联调，保持关闭。自动策略仍仅模拟，不会自动调用这些实盘接口。DeepSeek仍只生成研究建议。

免费美股报价说明：[Alpaca Market Data FAQ](https://docs.alpaca.markets/us/docs/market-data-faq)。IEX不是全美综合SIP。

限流处理：日线同步会复用已有最新完整 UTC 日线，美股成功快照缓存15分钟；遇到 HTTP 429、OKX 50011 或 Alpha Vantage 配额提示时，按数据源保存冷却状态，遵守 Retry-After 并指数退避（默认1至15分钟）。冷却期间不再请求该源，保留历史数据及原更新时间，并显示可重试时间。下一次同步在冷却到期后重试。

DeepSeek 模型选择：保存 API Key 后自动调用官方 GET /models 获取该账号可用模型，使用下拉列表由用户选择并保存，不写死模型或自动选择第一项。模型列表在当前页面内存中缓存5分钟；点击重新获取可立即请求，失败时显示原因并可手动重试；已有且仍可用的选择会保留。

页面性能：配置状态使用单次查询读取存在性，仅解密模型名称；与密钥无关的页面和数据读取路由不再读取密钥。页面内存缓存非敏感配置状态60秒，模型列表独立加载与合并并发请求，保存立即更新状态且不会等待模型接口。市场状态与选中标的并行读取，状态接口的独立数据库查询并行执行。缓存不写入浏览器持久存储。

美股日线：配置 Alpaca Key/Secret 后优先从 IEX 获取最近550天内已完成日线，处理分页并按纽约交易日期统一时间戳；价格未复权，成交量仅覆盖IEX。未配置Alpaca时使用Alpha Vantage。成功切换数据源时替换样本并暂停相关模拟策略，避免混用来源；失败保留原数据及来源。

观察列表：选择标的后可点击「删除标的」。删除与停止该标的运行/暂停中的模拟策略在一个事务内完成，版本冲突会拒绝删除。历史回测、模拟成交与运行日志保留，再次添加不会恢复旧策略。

## 自定义与 AI 策略

「策略回测」支持选择「自定义规则」，编辑入场 entry / 离场 exit 的 JSON；每组1–8条条件，all/any 组合。支持 OHLCV、SMA/EMA 快慢均线、RSI14、成交量均线和此前区间高低点；比较符为 gt/lt/gte/lte/crossAbove/crossBelow。离场优先，信号只使用当日及以前数据，不执行任意程序代码。

在「服务接入」保存 DeepSeek Key 并从接口返回列表选择模型后，在「策略回测」填写目标并生成候选。AI 不改动初始资金、手续费、滑点，不能提高仓位和回撤上限。应用、保存和启动模拟仍由用户操作，候选生成不提交订单。

### 研究窗口与验收

首次研究冻结完整数据快照、SHA-256、来源和复权口径，至少240根。前80%为开发数据，后20%封存为最终验收。开发前半段提供初始模型上下文，后半段分为3个不重叠的时间区间进行滚动评估；每折独立重置资金，指标只使用当时及过去数据。开发反馈参与下一候选，所以开发指标不能称为独立样本外表现。

默认每次2个候选，可选1–3个；每个窗口最多12次尝试，无效、重复、超时也计入。候选按每折平均（扣费收益 - 1.5 × 最大回撤）比较，同时要求累计至少12次平仓、每折至少2次、至少2折改善、无回撤停机、双倍成本平均收益为正、相邻均线周期评分下降不超过2个百分点。门槛是工程筛选策略，不是统计显著性或收益保证。所有未通过原因会展示，候选不会自动应用。

点击「冻结此方案并进行最终验收」后，该窗口只能验收这个不可变候选；重试同一候选返回相同结果。验收要求开发通过、数据口径可用、至少5次平仓、评分超过原策略且未触及回撤限制。无论通过与否，结果保留且禁止继续优化该窗口。至少积累60根新的同周期K线后才创建下一窗口，下一验收区间必须晚于上次验收终点。冻结版本可载入并手动启动向前模拟；日线历史开盘成交不等于实际券商执行。

### 实验记忆与指标

service_state 保存 research_session（完整数据）、research_attempt（目标、提示词、上下文、模型、失败与预算）、strategy_experiment（规则与哈希、基线、评分、成本压力、版本、引用记忆）。旧版未记录数据边界的实验不参与检索。检索按同标的、同来源、同复权口径、引擎版本和开发截止时间过滤，再按行情状态、日期、去重选择最多5条，同时保留成功与失败案例。向模型发送明确字段白名单，不发送最终验收结果或旧模型的推测性解释。历史本地模拟只提供截止日前的成交事实，并明确不是券商实盘成交；当前仓位不能由记忆推测。

featureSeries 为展示、AI 分析、回测和模拟共用的因果计算器。除原有字段，规则可使用 MACD/信号/柱/柱变化、ATR及价格占比、布林带上下界/宽度/位置、20日波动率及历史分位、相对成交量、成交金额、均线斜率、价格偏离均线ATR倍数、RSI变化、5/20/60日收益。模型得到最新值、过去60日摘要和近10日变化，而非只有一天快照。收益、比例和百分位为小数，RSI为0–100。市场基准从本地SPY/BTC历史按相同日期对齐，缺失时明确返回不可用。模型自评分未校准，不是胜率。

### 研究数据与可复现性

后台为Alpaca美股额外缓存近5年拆股复权日线，以及SPY研究基准；每24小时最多全量更新一次，以免新拆股后混合不同调整因子。研究缓存与原始报价、模拟成交数据独立，失败保留旧数据，不因页面打开而请求供应商。已建立的研究窗口继续使用冻结快照，不随后台修订改变。研究价格不计现金分红，也不是总收益；IEX成交量不是全市场成交量。CSV/Alpha复权未核实、明显跳变和长缺口会阻止最终验收标为通过。虚拟币使用现有完整现货日线；不足750根提示行情覆盖有限。财报、资金费率、持仓量等无可靠历史来源时不会编造或自动填值。

这套流程不能排除模型预训练已见历史行情，也不提供多重试验校正后的统计置信度；真实效果须依靠冻结后的向前观察。尚未实现自动券商交易。

所有者API：GET/POST `/api/strategies`、POST `/api/strategies/propose`（可选rounds:1–3）、GET `/api/strategies/research?asset=...`、POST `/api/strategies/finalize`（experimentId）。POST要求同源Origin与X-Trading-Request。生成与验收共享300秒租约，完成后15秒冷却；每次模型请求超时60秒，后续候选仍受持久预算限制。历史实验读取只访问D1。

## 自动交易接入方案

现状：规则引擎、策略版本、回测和本地模拟组合已具备；后台同步会推进用户已启动的模拟策略。Schwab 有人工预览/提交/撤单接口但实盘开关关闭；OKX 已有模拟盘自动执行和受开关保护的实盘手动提交；Alpaca 目前仅用于行情。

Alpaca Paper 后续可沿用以下执行流程，OKX Demo 已实现对应现金现货链路：固定策略版本 → 完整行情/时钟检查 → 持仓与余额对账 → 确定目标仓位 → 风控限制 → 持久订单意图 → 提交 → 查单/成交回报 → 更新订单与持仓。信号键为策略版本、标的、K线时间与方向，数据库唯一约束保证同一信号只产生一个意图；请求超时转为 unknown 并查单，不能盲目重发。

- Alpaca 使用纸面账户独立域名和 client_order_id，配合账户/订单查询或 trade_updates；当前已保存的是 Paper Key，可在实现执行器后完成纸面联调。
- OKX 使用独立 Demo Key、Secret、Passphrase 和 x-simulated-trading: 1；根据产品精度、最小数量处理现货订单，clOrdId 在本数据库永久唯一。模拟与实盘密钥分开配置，实盘下单受服务端开关及逐笔确认保护。
- 执行前检查行情新鲜度、余额、交易时段、价差、最小下单额、最大仓位与每日亏损；异常时停止新单并保留对账任务。
- AI 负责生成/优化候选策略，经过验证、保存并激活版本后才交给确定性执行器。不能用一次不受约束的模型回复直接拼订单。

定时5分钟行情快照适合当前研究界面；实际交易信号触发时仍须获取新鲜行情/账户状态，行情缓存与交易执行不能共用“永不请求”的规则。日线回测中的历史次日开盘成交只是模拟假设；自动交易须改为信号形成后在真实可交易时段提交，记录实际成交。

官方参考：[Alpaca Paper Trading](https://docs.alpaca.markets/docs/paper-trading) · [Alpaca Client Order ID](https://docs.alpaca.markets/us/v1.4.2/reference/getorderbyclientorderid) · [OKX API / Demo Trading](https://www.okx.com/docs-v5/en/)。

## 自选列表管理

观察列表统一提供添加、逐项勾选、全选和「删除选中」；删除前展示所选代码，停止对应模拟策略，保留历史回测、成交和日线归档。批量删除校验全部标的的 revision，任何版本过期都不删除仍存在的其他标的。当前最多跟踪12个标的。

添加美股时可按代码或英文公司/基金名称搜索，显示代码、完整名称、交易所与已添加状态。使用 Alpaca GET `/v2/assets?status=active&asset_class=us_equity` 的活跃美股目录，包含股票与 ETF；并非全球所有证券。目录每日由后台同步到 D1，按500条分块存储并原子发布；供应商失败保留旧版本，5分钟冷却。搜索接口仅查询数据库，不随输入请求供应商；每页50条，显示总匹配数，通过「加载更多匹配」遍历全部结果。虚拟币仍通过 USDT 现货交易对代码添加。

新增 GET `/api/stocks/search?q=...&offset=...`，及 POST `/api/assets/remove` 的 `{assets:[{assetId,revision}]}` 批量格式；均要求所有者身份，删除另需同源 CSRF 校验。单标的旧格式继续兼容。

## 策略工作台与草稿管理

「策略回测」改为统一工作台：左侧按草稿、AI候选、已保存版本、回收站分类，可按名称/代码搜索、按标的筛选、每页40条加载；列表只读取数据库摘要。右侧编辑名称、参数、规则和目标；草稿在停止输入约800毫秒后写入D1，允许保存尚未完整的数字或JSON编辑，正式回测和保存版本时仍执行完整校验。刷新恢复同浏览器上次选中的草稿（sessionStorage只存草稿ID），跨设备可从列表载入。

草稿有版本号并串行保存；冲突时保留当前编辑，提示另存副本或重新载入，不能覆盖其他页面的新版本。切换应用页签、运行回测和启动模拟前先完成保存；载入其他方案时暂时锁定编辑器以防迟到响应覆盖新输入。每个版本和AI候选均可复制为独立草稿，目标与来源关系随副本保留。已保存版本的重命名使用独立显示元数据，原始策略参数和研究记录不变。

支持勾选本页或多项批量移入回收站、恢复；一次操作校验全部元数据版本，发生冲突时全部拒绝。移入回收站只隐藏工作列表项目，不删除实验记忆、验收记录，也不停止已有模拟。归档中的草稿拒绝继续自动写入，恢复后可继续编辑。以前保存的版本和AI候选自动出现在列表中；此前仅存在浏览器内存、从未保存的编辑无法从服务端恢复。

所有者接口：GET `/api/strategy-library?kind=draft|experiment|version|trash&q=...&asset=...&offset=0`、GET `/api/strategy-library/item?kind=...&id=...`、POST `/api/strategy-drafts`、POST `/api/strategy-library/manage`。管理动作为archive/restore/rename，批量最多200项，POST沿用同源CSRF保护。草稿主体保存在strategy_draft:*，列表显示名称/回收状态在strategy_item_meta:*，无需修改原实验与版本记录。

## 策略工作台性能

草稿保存只等待数据库写入确认，列表不再进入保存与页面切换的等待链。匹配的当前首页用保存返回值更新；加载多页或筛选边界变化时后台重新读取摘要。按分类/搜索/标的/页码缓存摘要30秒、最多24页，合并相同并发读取；本页修改立即失效旧缓存并拒绝迟到响应。返回页面或窗口获焦时检查缓存，列表「刷新」强制读数据库。草稿详情始终重新读取，版本号校验、冲突恢复和身份保护保持不变；缓存仅存在当前页面内存。

进入编辑页不再自动下载最近回测的完整曲线和成交；点击「打开最近一次回测」或历史「查看」后读取。展示指标使用共用公式的最新值路径，保留EMA/RSI/ATR的历史递推，仅跳过不展示的历史滚动窗口；研究和回测仍计算完整因果序列。策略前缀查询使用可利用主键索引的GLOB，摘要与计数并行读取；正常草稿保存由4次数据库查询缩减到2次，写入RETURNING直接返回已保存版本。

回归检查覆盖全部显示指标与完整序列的一致性、保存查询数、迟到列表响应、缓存强制刷新、并发合并，以及桌面/手机的草稿保存、冲突恢复、回收站和AI候选操作。

## 无全页锁的标的切换

股票/币种切换使用独立读取生命周期，不再进入写操作的全页按钮锁，也不重建自选列表、报价表和勾选框。点击先更新选中反馈，异步读取后只替换详情区域；等待时保持其他标的和页签可点击，详情内的导入、分析和回测入口暂时禁用，避免对尚未确认的标的操作。连续点选取消前一个请求，响应须同时满足当前序号、页签和详情容器仍有效才能提交；失败保留原标的详情并允许重试。切换页面、数据库重读或写操作会取消未完成选择。

价格图按不可变历史数组复用生成结果；数据库 revision 变化或移除标的时释放旧日线缓存，新数组生成新图。金额/日期格式化器复用实例，图表更新前给浏览器一次绘制选中反馈的机会。全量行情和回测计算口径不变，没有为加速删减历史数据。


## 15分钟策略周期

在「策略回测 → 我的策略」选择「K线周期 → 15分钟」，点击「准备周期数据」，再运行回测、AI 优化或启动模拟。草稿、复制、保存版本、候选与历史回测都保留周期。旧策略缺省为日线。指标窗口以K线根数计算，例如 RSI14 为14根所选周期K线。

首次准备会注册该标的的15分钟数据订阅。美股需要已有 Alpaca Key/Secret，使用 IEX 的 `15Min` 未复权数据，初次读取近30天并处理分页，只保留纽约时间工作日09:30–16:00的完整K线，按时区处理夏令时。虚拟币读取 OKX 现货 `15m`，初次取900–1200根已确认K线。Alpha Vantage 日线、CSV 日线和即时报价各自保留原用途。IEX 成交量仅覆盖该交易所。美股15分钟研究的复权口径标为未核实，最终验收的数据质量门槛会阻止其标记为通过。

既有主机 cron 每5分钟调用签名同步接口。后台仅更新已注册标的，每个完成的15分钟时段成功检查一次，留30秒供数据源完成K线。正常情况下，整点、15分、30分、45分收盘的K线会在随后一次5分钟检查中处理，供应商延迟和限流会增加等待时间。任务依赖该主机 cron 在线运行。页面打开和周期选择只读取数据库，手动「准备周期数据」触发首次入库及后续显式检查。

分钟数据独立存于 D1 的 `market_series:15m:<assetId>`，活跃窗口最多2000根，历史按月归档到 `history:15m:*`。同步采用单标的租约、代次校验和去重，失败保留旧数据，删除标的取消订阅。分钟数据入库和日线更新独立，日线 CSV 导入仅暂停对应日线模拟。研究窗口、AI记忆、执行证据和基准对齐也按周期隔离，15分钟基准需要先准备对应 SPY / BTC 数据。

持续模拟在新K线完成后，用上一根的信号和该根的历史开盘价重建假想成交。因此信号产生到模拟成交记录可见，还需等待执行K线完成并被同步。当前自动运行模式为本地模拟，券商及交易所的自动下单尚待实现。时间水位防止重复推进，分钟历史缺口或水位丢失会暂停模拟。美股跨交易日间隔允许通过，目前时段过滤未内置交易所节假日、半日市及停牌日历。运行曲线保留最近2000点、成交列表保留最近1000笔，已入库的事件日志与月度行情归档用于历史审计。

验证覆盖分钟数据分页、未收盘过滤、纽约时区边界、独立持久化、删除竞态、归档失败重试、模拟去重与缺口暂停、AI周期约束与记忆隔离，以及桌面和移动端周期保存与操作请求。

## Schwab 接入检查与订单核对

Schwab 授权绑定用户、回调地址及应用配置代次。应用 Key/Secret 的变更原子保存并使旧授权失效，保存相同值保留已有授权。所有配置字段先完整验证，再写入加密值。访问令牌响应需包含合法有效期，刷新保留最初授权时间，页面提示重新授权。令牌刷新和授权回调使用持有者租约及版本校验，过期请求不能释放后继租约或覆盖新配置、新授权。预计重新授权时间按最初授权后约7天提示，实际失效以 Schwab 响应为准。

订单支持 NORMAL / DAY、股票整股限价、多头买入及已有多头持仓卖出，单笔名义金额上限1000 USD。预览和提交分别检查已授权账户、可交易现金和多头持仓。卖出时保守扣除近一年未结束订单及子订单的待卖数量，数量无法核实或达到查询上限时停止提交。此预检只覆盖该接口支持的订单类型，券商仍需检查交易权限、账户限制、市场状态及成交条件。交易结果以券商订单和账户查询为准。

操作按以下状态持久保存，记录 ID 可在「服务接入 → 订单操作记录」读取。

- `prepared` 是有效期60秒的本地预览。修改页面参数、切换授权或修改应用配置后需重新预览，提交时再次校验有效期。
- `sending` 是已经认领的提交，单账户的并发认领使用数据库条件更新。重复点击同一预览不能再次发送。
- `accepted` 是响应含同源、同账户的可核实订单编号。需查询该订单后再允许新提交。该状态仅表示受理。
- `unknown` 用于网络超时、5xx 或成功响应缺少可核实编号。账户暂停新提交，禁止以新预览绕过。先查询最近7天券商订单（最多100笔），将编号与操作记录核对。关联时校验代码、方向、数量、限价、发送时间和重复绑定，无法唯一核实的情况需在券商端人工核对。
- `working`、`filled`、`canceled`、`rejected` 等来自券商订单查询，分别保留 `brokerStatus`、已成交和剩余数量。关联操作返回的券商明细始终需要结合当前账户持仓检查。
- 撤单记录按账户及订单编号去重。`cancel_pending` 表示撤单请求已受理，`cancel_unknown` 表示结果不明。查询可能发现订单已经成交，应按实际成交处理。明确拒绝的撤单可由用户再次发起，结果不明的撤单保留记录并先核对。

旧版本已受理记录可用保存的合法 Location 查询；旧预览需重新生成。旧发送中记录若缺少发送时间，继续保留待确认并提示券商端人工核对。账户持仓、权限及令牌的真实联调需要用户自己的 Schwab 应用和账户。自动策略目前仍由本地模拟服务推进，Schwab 下单需使用独立的手动确认入口及实盘配置开关。

本次验证使用内存数据库与模拟 Schwab HTTP 响应，覆盖配置部分失败、OAuth 回调、令牌刷新竞争、应用变更、重复提交、结果不明、余额及持仓、订单编号校验、状态核对和撤单竞态。接入真实账户后仍需完成只读授权、账户权限、响应字段与正常交易时段的联调。官方入口见 [Schwab Trader API](https://developer.schwab.com/products/trader-api--individual)，令牌与订单响应参考维护者的 [认证说明](https://schwab-py.readthedocs.io/en/latest/auth.html) 和 [订单编号说明](https://schwab-py.readthedocs.io/en/latest/util.html)。


## OKX 现金现货执行

「服务接入 → OKX 账户与现货交易」提供独立的模拟盘及实盘 API Key、Secret Key 和 Passphrase 输入，留空保留已有值。配置以服务端密文保存，页面仅返回是否已配置。区域可选全球、美国、欧洲，使用对应官方 API 域名。模拟盘必须使用 OKX 模拟交易中创建的密钥，所有模拟请求携带 `x-simulated-trading: 1`。客户端不能启用 `OKX_LIVE_TRADING_ENABLED`，此服务端开关启用后，实盘提交及撤单还需逐笔确认。API 只需读取和交易权限。

支持 USDT 现金现货限价交易，适用 OKX 现货模式、合约模式中的现货交易；跨币种和组合保证金账户模式暂不支持。预览与提交均核实账户 UID、当前余额、交易对状态、tickSz / lotSz / minSz 及新鲜报价。金额和数量采用24位定点整数校验，单笔不超过1000 USDT，限价与当前买卖报价的偏离上限5%，买入预留0.5%成本缓冲。委托提交用服务器时间校准、完整查询串及原始 JSON 正文签名，并设置请求截止时间。

每笔逻辑订单分配唯一 clOrdId，在数据库中先记录意图，再使用条件更新认领。超时、5xx 或无法核实的成功响应记为 unknown，通过原 clOrdId 或 ordId 查询，不重放下单 POST。HTTP 200 仍检查业务 code 与逐笔 sCode。同环境账户存在未结束或待确认操作时暂停新的下单意图。交易所查单校验 UID、代码、方向、限价、数量及单调递增的累计成交量，保留部分成交、均价和手续费。撤单独立去重并保存状态，撤单受理仍需要最终查单，最终状态同时更新原订单。这里只管理本平台发出的委托；交易所查询还可查看指定交易对最近的待成交和历史订单。

在「策略回测」可明确启动 OKX 模拟盘策略，配置被复制为不可变执行参数。后台沿用现有主机每5分钟同步任务，只在新完整K线后计算信号，使用当前交易所报价生成限价委托，不回放历史开盘成交。预算为初始资金与1000 USDT的较小值，按所选仓位比例买入；策略只出售自身订单累计获得、扣除基础币手续费后的数量。委托结束后按交易所实际均价和手续费更新独立策略账本，部分成交可在订单记录中查看。手续费若不在基础币或USDT中，或无法核实，策略暂停待查。

最多同时运行3个模拟策略，同一账户及标的仅1个。账户有其他未结束委托时等待，超过两个周期仍未结束的策略委托会申请撤单。历史缺口、配置变化、无法核实的账本或触及回撤阈值会暂停新信号。停止或删除标的停止新信号，已经发往交易所的委托和持仓需单独查询、撤单或处置。该模块提供模拟盘自动执行及实盘手动确认入口，尚未提供实盘自动策略启动。页面打开只读取数据库配置状态、操作记录和策略快照，联网操作由明确点击或后台已启动任务触发。

验证涵盖请求签名、环境隔离、业务错误、精度、资金、重复提交、超时查单、撤单竞态、配置变化、策略水位、成交手续费、暂停及停止，并覆盖桌面与移动端完整操作。真实交易所联调需补齐对应环境的三项凭据。官方参考见 [OKX V5 API](https://www.okx.com/docs-v5/en/)。
